# 한국무브넥스 ECT 검사 데이터 분석

**ECT 검사기의 NG 데이터를 위치별로 비교하고, 다시 확인할 순서를 정리하는 프로그램입니다.**

아래 순서대로 따라 하면 코드를 작성하지 않아도 **데이터 수량 확인 → 모델 실행 → 그래프 확인 → 결과 저장**까지 할 수 있습니다. 기본 분석은 일반 PC의 CPU로 실행합니다. GPU나 별도 딥러닝 설치는 필요하지 않습니다.

> **처음 사용하시는 분:** ① 이 저장소를 내려받고 ② `install_windows.cmd`를 한 번 실행한 뒤 ③ `start_notebook.cmd`를 실행하세요. 노트북에서 **Run → Run All Cells**를 누르면 연습용 분석을 확인할 수 있습니다.
>
> 저장소에는 **합성 연습 데이터만** 들어 있습니다. 실제 회사 분석은 별도 전달받은 CSV가 필요합니다. 연습용 그래프·수량을 실제 회사 성능으로 사용하지 마세요.

## 1. Windows에 설치하기

### 1-1. 준비물

- Windows 10/11 64비트 PC
- Python **3.12 64비트**와 Python Launcher
- 처음 설치할 때 인터넷 연결
- 실제 회사 분석을 할 경우 별도 전달받은 분석용 CSV

기본 모델은 CPU로 실행합니다. 메모리 8GB 이상을 권장하며, 다른 프로그램을 많이 켜 두었다면 닫은 뒤 실행하세요. 설치할 때 받아야 하는 파일이 있어 사내망에서 다운로드가 막히면 전산 담당자에게 문의하세요.

### 1-2. Python 설치

1. [Python Windows 다운로드](https://www.python.org/downloads/windows/)에서 Python 3.12용 64비트 설치 파일을 준비합니다.
2. 설치 화면에서 **Python Launcher** 설치 항목과 **Add Python to PATH**를 선택합니다.
3. 설치를 완료합니다. 이미 Python 3.12와 Launcher가 있으면 다시 설치할 필요가 없습니다.

새 버전의 Python이 이미 있어도 이 프로그램은 3.12 환경을 따로 만듭니다. `install_windows.cmd`는 `py -3.12` 명령으로 해당 버전을 찾습니다. 3.12 설치 파일은 [3.12.10 공식 배포 페이지](https://www.python.org/downloads/release/python-31210/)에서도 확인할 수 있습니다. 회사에서 제공하는 최신 보안 수정 3.12 환경이 있다면 그 환경을 사용하세요.

### 1-3. 프로그램 내려받기

1. 이 GitHub 페이지의 초록색 **Code** 버튼을 누릅니다.
2. **Download ZIP**을 누릅니다.
3. 받은 ZIP을 마우스 오른쪽 버튼으로 눌러 **모두 압축 풀기**를 선택합니다.
4. 압축을 푼 폴더를 엽니다. `README.md`, `install_windows.cmd`, `notebooks`가 보이면 맞는 폴더입니다.

예를 들어 `C:\MovenexECT`처럼 찾기 쉬운 위치에 두세요. **ZIP 안에서 바로 실행하지 말고 반드시 압축을 먼저 풉니다.**

Git을 사용하시는 분은 다음 명령으로 받을 수도 있습니다.

```powershell
git clone https://github.com/barraki72268-sketch/Koreamovenex.git
cd Koreamovenex
```

### 1-4. 설치 파일 실행 — 처음 한 번

`install_windows.cmd`를 더블클릭합니다.

창에서 다음 작업이 차례로 진행됩니다.

1. Python 3.12 확인
2. 이 프로그램 전용 실행 환경 `.venv` 생성
3. 분석 프로그램과 Jupyter 설치
4. 설치 상태 확인 및 노트북 연결

**‘설치 완료. start_notebook.cmd 파일을 실행하세요.’**가 나오면 설치가 끝난 것입니다. 중간에 오류가 나오면 마지막 문구까지 확인하고 [문제 해결](#9-자주-막히는-부분)을 보세요. 설치 도중 창을 닫으면 설치가 끝나지 않을 수 있습니다.

명령으로 설치하려는 분은 프로젝트 폴더에서 아래 순서대로 실행합니다. PowerShell 실행 정책을 바꾸거나 가상환경을 활성화할 필요는 없습니다.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m ipykernel install --sys-prefix --name movenex-ect --display-name "Python (Movenex ECT)"
```

## 2. Jupyter 노트북 실행하기

### 2-1. 화면 열기

1. `start_notebook.cmd`를 더블클릭합니다.
2. 웹브라우저가 열리고 **01_처음부터_분석하기.ipynb**가 표시됩니다.
3. 실행 환경 선택창이 나타나면 **Python (Movenex ECT)**를 선택합니다.

브라우저가 자동으로 열리지 않으면 실행창에 표시되는 `http://127.0.0.1:8888/...` 주소 전체를 복사해 브라우저에 붙여 넣으세요. 주소에 붙는 로그인용 문자열은 다른 사람에게 공개하지 않습니다.

### 2-2. 처음에는 연습 데이터로 실행

노트북의 기본 설정은 아래와 같습니다.

```python
DATA_MODE = "demo"
```

이 상태에서는 저장소에 포함된 **가상으로 만든 연습 데이터**를 사용합니다. 실제 회사 데이터가 없어도 프로그램의 실행 순서를 익힐 수 있습니다.

상단 메뉴에서 **Run → Run All Cells**를 누릅니다. 한국어 설명 아래에 표와 그래프가 차례로 나타납니다. 마지막에 **‘저장 완료’**가 나오면 결과 파일까지 생성된 것입니다.

### 2-3. 한 칸씩 실행하며 확인하기

노트북은 설명과 실행 칸이 번갈아 나오는 문서입니다. 실행 칸을 **셀**이라고 부릅니다.

| 화면에서 할 일 | 동작 |
|---|---|
| 한 칸 실행 | 실행할 칸 클릭 → 상단 `▶` 또는 `Shift + Enter` |
| 처음부터 전부 실행 | `Run → Run All Cells` |
| 실행 중인지 확인 | 칸 왼쪽의 `[*]`가 숫자로 바뀌면 해당 칸 완료 |
| 설정을 바꾼 뒤 다시 실행 | `Kernel → Restart Kernel and Run All Cells…` |
| 실행 중단 | 상단 `■` 또는 `Kernel → Interrupt Kernel` |
| 노트북 화면 저장 | `Ctrl + S` |

**위에서 아래로 실행하세요.** 중간 칸부터 실행하면 앞에서 만든 데이터가 없어 오류가 날 수 있습니다.

### 2-4. 실제 회사 데이터로 실행

1. 별도 전달받은 `C10A_49513-75270R.csv.gz`를 `data/private` 폴더에 넣습니다. `.gz`는 용량을 줄인 CSV이며 **압축을 풀 필요가 없습니다.**
2. 노트북 ② 단계에서 아래 한 줄을 바꿉니다.

```python
DATA_MODE = "company"
```

3. `PRODUCT = "C10A_49513-75270R"`가 맞는지 확인합니다.
4. **Kernel → Restart Kernel and Run All Cells…**를 누릅니다.
5. 노트북에 **‘실제 회사 데이터입니다’**라는 안내가 나오는지 확인합니다.

회사 데이터는 Git 저장소에 들어 있지 않습니다. `data/private`에 파일이 없으면 명확한 안내와 함께 중단합니다. 실제 파일이 없을 때 회사 결과를 임의로 만들어 표시하지 않습니다.

## 3. 전체 흐름 — 무엇을 넣고 무엇이 나오나요?

![전체 분석 흐름도](docs/images/01_전체_분석흐름.png)

| 단계 | 들어가는 것 | 프로그램이 하는 일 | 사용자가 확인할 것 |
|---|---|---|---|
| ① 데이터 준비 | 원본 Excel + 기업 색상 판정 Excel, 또는 표준 CSV | 측정값을 기준으로 기업 판정을 연결하고 CSV로 변환 | 다른 품번끼리 연결하지 않았는지 |
| ② 수량 점검 | 위치별 측정행 | 기간·수량·주파수 구성·결측·중복 확인 | 파일이 빠지거나 중복 추가되지 않았는지 |
| ③ 대상 구분 | OK / NG / 마스터 / 오류 / 0·노랑 | 오류·미확인 제외, 일반 NG와 마스터 구분 | 제외 사유와 라벨 수량 |
| ④ 위치 분리 | 위치 1 데이터 / 위치 2 데이터 | 위치마다 별도 입력·기준·모델 생성 | 위치 2 라벨을 위치 1에 넘겨 쓰지 않음 |
| ⑤ 날짜 구분 | 학습·기준 설정·시험 날짜 | 과거로 학습하고 이후 날짜 결과를 별도로 비교 | 시험 날짜가 학습에 들어가지 않았는지 |
| ⑥ 비교 | 주파수별 X/Y 값 | 거리 기준, Random Forest, XGBoost 실행 | 전체 수량과 시험 날짜 수량을 구분 |
| ⑦ 시각화 | 모델 점수·기업 판정 | 위치별 PCA·가성 구분 수·진성 점수·주파수 X/Y 그래프 | 겹치는 분포, 보류 수, 진성 누락 여부 |
| ⑧ 저장 | 표·그림·모델·설정 | 실행 시각별 결과 폴더 생성 | HTML 보고서, CSV, PNG |

현재 기본 날짜는 다음과 같습니다. 이 날짜는 **C10A 기존 결과 재현용**입니다. 다른 기간의 데이터로 재학습할 때는 직접 바꿉니다.

| 구간 | 날짜 | 용도 |
|---|---|---|
| 학습 | 2026-08-20까지 | 정상 분포·모델 학습 |
| 기준 설정 | 2026-08-20 이후 ~ 2026-10-07 | 거리 임계값 설정 |
| 시험 | 2026-10-07 이후 | 이후 날짜 결과 비교 |

코드에는 종료일을 고정해 두었습니다. 새 날짜의 CSV를 붙여도 과거 시험 날짜가 자동으로 학습 구간으로 이동하지 않습니다.

## 4. 결과를 저장하는 방법

### 4-1. 저장은 마지막 칸에서 자동으로

01번 노트북의 **⑧ 결과 저장**까지 실행하면 아래처럼 새 폴더가 만들어집니다. 같은 분석을 다시 실행해도 이전 결과를 덮어쓰지 않습니다.

```text
results/
└─ 실행날짜_시각/
   ├─ 결과보고서.html
   ├─ 01_위치별_결과요약.csv
   ├─ 02_행별_판정근거.csv
   ├─ 03_제외행과_이유.csv
   ├─ 04_모델별_입력중요도.csv
   ├─ 05_거리기반_상세점수.csv
   ├─ 01_PCA_위치별_분포.png
   ├─ 02_전체NG_가성구분.png
   ├─ 03_시험날짜_가성구분.png
   ├─ 04_진성행_점수.png
   ├─ 05_주파수_XY_비교.png
   ├─ 실행설정과_이력.json
   └─ models/
      ├─ p1_master_proxy_RandomForest.joblib
      ├─ p2_master_proxy_XGBoost.joblib
      └─ ...
```

### 4-2. 어떤 파일을 열면 되나요?

| 목적 | 파일 | 여는 방법 |
|---|---|---|
| 결과를 한눈에 보기 | `결과보고서.html` | 탐색기에서 더블클릭 → 브라우저 |
| 위치별·모델별 수량 확인 | `01_위치별_결과요약.csv` | Excel로 열기 |
| 특정 NG의 판정 확인 | `02_행별_판정근거.csv` | 원본 시트·행, 위치, 모델, 점수, 판정 확인 |
| 빠진 데이터 이유 확인 | `03_제외행과_이유.csv` | 0/노랑, 오류, 라벨 확인, 결측 등 확인 |
| 모델이 사용한 입력 확인 | `04_모델별_입력중요도.csv` | 위치·모델·주파수별 중요도 확인 |
| 발표나 보고에 그래프 사용 | `.png` 파일 | PowerPoint에 그림으로 삽입 |
| 같은 조건으로 다시 실행 | `실행설정과_이력.json` | 입력 해시, 날짜, 버전, 설정 확인 |
| 학습 없이 새 데이터만 판정 | `models/*.joblib` | 02번 노트북의 ⑤ 단계에서 사용 |

CSV는 한글이 깨지지 않도록 Excel에서 읽기 쉬운 UTF-8 형식으로 저장합니다. 점수는 `positive_score`, 판정은 `decision`과 한국어 `판정` 열에 있습니다.

**노트북 화면을 저장하는 `Ctrl + S`와 분석 결과 저장은 다릅니다.** 결과 파일은 반드시 ⑧ 칸을 실행해야 생성됩니다. HTML 보고서를 전달할 때는 PNG도 함께 필요하므로 **결과 폴더 전체를 압축해서 전달**하세요.

서버에서 실행한 파일은 서버에 저장됩니다. Jupyter 왼쪽 파일 목록에서 `results` 폴더를 열고 필요한 파일을 오른쪽 클릭해 **Download**로 내려받습니다. 많은 파일을 한꺼번에 전달할 때는 서버 담당자에게 결과 폴더 압축을 요청하세요.

![연습용 합성 데이터의 그래프 예시](docs/images/07_연습용_그래프예시.png)

### 5-1. PCA 분포 그림

위치 1과 위치 2를 각각 그립니다. 여러 X/Y 값을 두 축으로 줄여 점으로 표시합니다.

- 회색: 설비 OK
- 보라색: NG 마스터
- 초록색: 기업이 가성으로 표시한 NG
- 주황색 별: 기업이 진성으로 표시한 NG
- 노란색: 아직 기업 판정이 없는 NG

가까운 점들은 축소한 화면에서 비슷하게 보이는 데이터입니다. **PCA는 분포를 보기 위한 그림이며, 그림에서 멀어 보인다는 이유만으로 진성·가성을 확정하지 않습니다.** 실제 모델은 원래의 여러 X/Y 입력을 이용합니다. PCA 축에는 원래 X/Y 단위가 없습니다.

### 5-2. 가성 구분 수 막대그래프

각 모델이 기업 가성 데이터 중 몇 행을 **가성 후보 / 보류 / 진성 의심**으로 분류했는지 보여 줍니다.

반드시 두 그래프를 함께 봅니다.

| 그래프 | 의미 |
|---|---|
| 전체 NG | 전체적인 수량 비교. **학습에 사용한 행도 포함** |
| 시험 날짜 NG | 학습 이후 날짜에서의 비교. 새로운 날짜에서 가성을 얼마나 구분했는지 확인 |

가성 후보가 많더라도 진성을 가성 후보로 보내면 문제가 됩니다. 아래 진성 점수 그림도 함께 확인하세요.

### 5-3. 진성 행 점수 그래프

마스터 기반 모델에서 기업 진성 행이 어느 쪽 점수를 받았는지 보여 줍니다.

| 점수 | 표시 | 의미 |
|---|---|---|
| 0.1 이하 | 가성 후보 | 학습한 반대쪽 패턴과 유사 |
| 0.1 초과 ~ 0.9 미만 | 보류 | 모델이 확실하게 한쪽으로 보내지 못함 |
| 0.9 이상 | 진성 의심 | 학습한 마스터 쪽과 유사 |

이 점수는 **실제 불량 확률 90%**라는 뜻이 아닙니다. 현재 고정한 분류 기준입니다. 기업 라벨 직접 학습에서 진성 2행을 다시 맞춘 결과는 이 그림의 독립 검증에 사용하지 않습니다.

### 5-4. 위치·블록·주파수 X/Y 그림

노트북의 `POSITION`, `BLOCK`, `FREQUENCY`를 바꾸면 특정 위치·블록·주파수의 원래 X/Y 값을 볼 수 있습니다.

```python
POSITION = 2
BLOCK = 1
FREQUENCY = "30.0Hz"
```

첫 블록 30Hz에서 진성·가성·마스터·OK가 어떻게 겹치는지 직접 볼 수 있습니다. 존재하지 않는 주파수를 선택하면 안내와 함께 중단합니다. 블록 1/2/3은 파일의 8슬롯 묶음이며 실제 설비 채널 명칭과의 대응은 확인이 필요합니다.

### 5-5. 입력 중요도

Random Forest와 XGBoost가 학습 과정에서 어떤 X/Y 입력을 많이 사용했는지 CSV로 제공합니다. **중요도가 높다고 불량의 물리적 원인이 입증된 것은 아닙니다.** 위치·주파수 확인과 현장 검토에 참고합니다.

## 6. 모델은 무엇을 어떻게 비교하나요?

### 6-1. 공통 입력과 출력

**입력:** 한 위치의 여러 주파수·블록에서 측정된 X/Y 값 → **출력:** 가성 후보 / 보류 / 진성 의심.

현재 C10A 기본 입력은 위치 1이 36개, 위치 2가 42개의 X/Y 값입니다. 프로그램은 위치별 활성 주파수 구성을 확인합니다. 날짜·색상·판정명·카운터·원본 행 번호·최대측정값은 모델 입력으로 넣지 않습니다.

같은 검사의 위치 1·2라도 **합쳐서 한 모델에 넣지 않습니다.** 각 위치의 정상 데이터, 마스터, 기업 라벨을 각각 사용합니다.

### 6-2. 거리 기반 기준 — ‘어떤 기준 샘플과 비슷한가?’

![거리 기반 기준 설명](docs/images/02_거리기반_구조.png)

정상 OK와 마스터를 기준점으로 놓고 새 NG가 어느 쪽에 가까운지 봅니다. 네 가지 방법이 데이터의 다른 면을 살핍니다.

| 방법 | 쉽게 말하면 | 코드에서 하는 일 |
|---|---|---|
| Robust L2 | 각 값의 평소 변동 폭을 맞춘 뒤 차이 비교 | 학습 OK의 중앙값·IQR로 크기를 맞추고 RMS 거리 계산 |
| Shrink Mahalanobis | 함께 움직이는 입력값의 관계도 고려 | 정상 공분산을 보정한 공간에서 거리 계산 |
| PCA 거리 | 정상 데이터의 주요 변화 방향을 고려 | 정상 변화량 95%를 담는 축에서 거리 계산 |
| Cosine | 전체 값의 방향·패턴 비교 | 크기를 정규화한 벡터 간 방향 차이 계산 |

최종적으로 **4개 중 3개 이상**이 동의하는지 봅니다. OK와 비슷한 NG를 가성 후보로 두고, 애매한 행은 보류합니다. **OK와 마스터 모두에서 멀다는 이유만으로 가성을 확정하지 않습니다.**

C10A 위치 2에는 기존 진성 2행을 검토한 뒤 추가한 **‘전체 OK 분포 이탈 + 첫 블록 30Hz의 마스터 유사성’** 보완 규칙이 있습니다. 이는 사후에 선택한 기준입니다. 위치 1에는 이 30Hz 규칙을 적용하지 않습니다.

### 6-3. Random Forest — ‘여러 개의 질문표가 판단하고 평균낸다’

![Random Forest 구조](docs/images/03_RandomForest_구조.png)

한 개의 나무는 ‘이 X값이 기준보다 큰가?’, ‘이 Y값이 기준보다 작은가?’ 같은 질문을 순서대로 합니다. Random Forest는 서로 다르게 만든 여러 나무의 결과를 모읍니다. 이 코드에서는 나무 **200개**, 최대 깊이 **4**를 사용합니다.

각 나무가 낸 두 종류의 점수를 평균해 최종 점수를 만들고, 0.1 / 0.9 기준으로 가성 후보·보류·진성 의심을 나눕니다. 적은 데이터에서도 비교 기준을 만들기 쉽지만, 진성 표본 자체가 부족한 문제를 해결해 주는 것은 아닙니다.

원리 참고: [scikit-learn Random Forest 공식 설명](https://scikit-learn.org/stable/modules/ensemble.html#forest). 그림은 이 저장소의 구현을 설명하기 위해 직접 작성했습니다.

### 6-4. XGBoost — ‘앞선 판단의 부족한 점을 다음 나무가 보완한다’

![XGBoost 구조](docs/images/04_XGBoost_구조.png)

작은 나무를 순서대로 더하면서 학습 데이터에서의 오차를 줄입니다. 이 코드에서는 최대 깊이 **2**인 나무를 **200단계**까지 쌓고, 한 번에 바뀌는 양을 작게 설정했습니다. 과도하게 복잡해지지 않도록 제약도 둡니다.

Random Forest가 여러 나무의 판단을 모으는 방식이라면, XGBoost는 앞 단계의 점수에 다음 나무의 보정값을 더하는 방식입니다. 최종 점수를 같은 0.1 / 0.9 기준으로 나눕니다.

원리 참고: [XGBoost 공식 설명](https://xgboost.readthedocs.io/en/stable/tutorials/model.html). 그림은 직접 작성했습니다.

### 6-5. ‘마스터 기반’과 ‘기업 라벨 직접 학습’은 다릅니다

| 구분 | 학습하는 두 종류 | 현재 해석 |
|---|---|---|
| 마스터 기반 `master_proxy` | NG 마스터 ↔ 설비 OK + 학습 날짜의 기업 가성 | 마스터와 유사한 패턴인지 비교. 기업 진성과 같은 사건그룹은 학습에서 제외 |
| 기업 라벨 직접 학습 `company_direct` | 기업 진성 ↔ 기업 가성 | 위치 1은 진성이 없어 생략. 위치 2는 진성 2행을 학습하므로 그 2행의 재분류는 학습 확인 |

현재 진성이 매우 적으므로, **직접 지도학습에서 2행을 맞췄다고 새 진성도 잘 찾는다고 말할 수 없습니다.** 노트북과 CSV는 학습 포함 여부와 시험 날짜 결과를 구분해 표시합니다.

### 6-6. TabICLv2 — 선택 비교 모델

![TabICLv2 사용 흐름](docs/images/05_TabICLv2_구조.png)

여러 종류의 표 데이터를 미리 학습한 모델에 기준 샘플과 새 샘플을 함께 넣어 비교하는 방식입니다. 그림은 이번 프로그램의 **사용 흐름을 단순화한 개념도**입니다. 내부의 모든 신경망 층을 표현한 설계도는 아닙니다.

설치 용량과 실행 부담이 있어 기본 실행에서 제외했습니다. 실행하려는 담당자는 [선택 모델 안내](docs/선택모델_TabICL.md)를 사용하세요. 원본 프로젝트는 [TabICL 공식 저장소](https://github.com/soda-inria/tabicl)입니다. 다른 2026년 모델 OFA-TAD는 코드와 구조를 검토한 단계이며 이 배포본의 실행·성능 비교 모델에 포함하지 않았습니다.

## 7. 추가 데이터가 오면 어떻게 하나요?

![추가 데이터 처리 흐름](docs/images/06_추가데이터_흐름.png)

상황에 따라 하는 일이 다릅니다.

| 받은 데이터 | 할 일 |
|---|---|
| 원본 Excel과 기업 색상 판정 회신본 | 02번 노트북 ①~②로 CSV 생성 |
| 이전 기간까지 모두 들어 있는 전체 회신본 | 새 CSV 한 개로 교체. 기존 CSV에 중복으로 덧붙이지 않음 |
| 날짜가 다른 추가분 CSV | 02번 노트북 ③으로 기존 CSV와 합치기 |
| 기존 행의 라벨만 수정한 회신본 | 수정된 CSV를 기준으로 교체·재학습 |
| 모델을 다시 학습하고 싶음 | 02번 노트북 ④, 학습·기준 설정 날짜 지정 후 재학습 |
| 저장 모델을 그대로 새 데이터에 적용 | 02번 노트북 ⑤, 모델 파일과 새 CSV 지정 |

CSV의 필수 컬럼, 색상 읽기 규칙, 중복 처리와 날짜 변경 예시는 [추가 데이터 가이드](docs/추가데이터_가이드.md)에 있습니다. 주파수 구성이 바뀐 데이터를 같은 모델에 넣으면 중단합니다. 품번·설비 조건을 확인한 뒤 분리하여 학습하세요.

## 8. 현재 제공 범위와 결과 해석

이 배포본의 중심은 **C10A 위치별 거리 보완 기준과 RF·XGBoost 비교 재현**입니다. 다른 품번도 같은 형식의 CSV로 수량과 분포를 확인할 수 있지만, 기존 결과와 동일한 학습·검증 조건이 성립하는지는 별도로 확인해야 합니다. C10A 전용 30Hz 보완 기준을 다른 품번에 적용하지 않습니다.

기업 진성/가성은 회신 Excel의 표시를 읽은 라벨입니다. 파괴검사 등 별도 최종 판정으로 독립 확인되었다고 가정하지 않습니다. C10A 진성은 위치 2의 2개 측정행으로, 같은 날짜·카운터에 있어 독립 제품 수가 미확인입니다. 시험 날짜에는 기업 진성이 없으므로 **새 날짜의 진성 검출률은 아직 평가할 수 없습니다.**

후속 확인에 필요한 것은 다른 날짜의 진성, 최종 재검사·처분 결과, 실제 제품을 식별할 검사 ID와 부위 정보입니다. 현재 결과는 자동 폐기나 출하 승인 대신 **재검토 우선순위를 정하는 참고자료**로 사용합니다.

## 9. 자주 막히는 부분

| 증상 | 확인할 내용 |
|---|---|
| Python 3.12를 찾을 수 없음 | Python 3.12 64비트와 Launcher 설치 후 `install_windows.cmd` 재실행 |

| DLL 로드 오류 | Windows 업데이트와 [Microsoft Visual C++ x64 런타임](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist) 설치 상태 확인 |
| 브라우저가 열리지 않음 | 실행창의 로그인용 URL 전체를 브라우저에 붙여 넣기 |
| Python 실행 환경이 다른 것 같음 | 노트북 커널을 `Python (Movenex ECT)`로 선택 |
| `NameError` | 처음 칸부터 실행. `Kernel → Restart Kernel and Run All Cells…` 사용 |
| 실제 CSV를 찾을 수 없음 | `data/private`의 파일명과 `PRODUCT` 확인. `.csv.gz`를 이중 확장자로 만들지 않기 |
| 학습 OK나 마스터가 부족하다는 안내 | 날짜 구간에 해당 데이터가 있는지 수량표 확인. 없는 데이터를 임의로 채우지 않기 |
| 주파수가 바뀌었다는 오류 | 품번·설비 조건이 다른 데이터인지 확인하고 별도 CSV로 분리 |
| 중복 행 오류 | 전체 회신본을 추가분으로 합치지 않았는지 확인 |
| 8888 포트가 이미 사용 중 | 기존 실행창 확인. Jupyter가 다른 포트로 열렸으면 실행창 URL 사용 |
| CSV 한글이 깨짐 | Excel의 데이터 가져오기에서 UTF-8로 열기 |
| Linux에서 한글이 네모로 보임 | 서버에 Noto Sans CJK 등 한글 글꼴 설치 후 커널 재시작 |

```text
│  ├─ raw/                       ← 회사 Excel, Git에 포함하지 않음
│  └─ processed/                 ← 새로 변환한 CSV
├─ results/                      ← 실행할 때마다 새 결과
├─ scripts/                      ← 담당자용 명령 실행 도구
└─ tests/                        ← 실행·분리 규칙 점검
```

설치 후에는 별도 모델 파일을 받지 않아도 기본 노트북에서 RF·XGBoost를 새로 학습합니다. 선택 모델만 추가 패키지와 체크포인트가 필요합니다. 원본 데이터는 변경하지 않습니다.
